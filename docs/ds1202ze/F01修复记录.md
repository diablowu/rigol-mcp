# F01 双通道兼容修复

分支：`codex/fix-ds1202ze-f01`。基线：`ef09519d634823ff9efb2852f8589ec719905e86`。

DS1202Z-E 和 DS1102Z-E 原先被当作四通道设备查询，导致状态读取访问 CH3/CH4，配置操作也可能在成功写入后因总状态读回失败而报错。本次增加不可变通道能力对象，根据 IDN 的型号字段选择双通道范围；原有 DS1054Z/DHO924S 的四通道行为保留。

修复内容：

- 状态快照只查询实际通道；通道配置、测量、双源测量、波形读取和边沿触发先验证全部源，再执行相关查询或写入。
- `set_channel`、`set_timebase`、`set_trigger` 在一次 `_call` 锁内完成写入与相关字段读回，保持原有返回字段。通道设置只读回当前通道，时基和触发设置不查询通道配置。
- MCP 工具枚举和说明使用当前能力。可设置 `RIGOL_MODEL=DS1202Z-E` 或 `DS1102Z-E`，在连接前提供双通道 schema；未配置时保留原有四通道初始 schema，调用 `idn` 后更新并通知客户端。实际运行校验以真实 IDN 为准，提示配置不会覆写仪器能力。
- 能力缓存与驱动缓存一起在断连时清除。没有扩展任意 SCPI 的权限或修改波形传输格式。

验证命令：`uv run --extra test pytest`，结果 **157 passed**（原有 129 项，加 28 项回归）。新增测试覆盖双通道/四通道状态查询、CH3/CH4 在相关 I/O 前拒绝、双源测量不产生部分副作用、合法 CH2/EXT/AC、能力缓存、工具 schema 和通知、服务启动的工具变更能力声明、配置局部读回以及 autoscale 双通道读回。

测试为离线 fake 仪器验证。ASCII 波形帧格式（F02）、采集重试（F03）和真实设备验收仍按原方案继续处理。历史 `baseline-audit.json` 保留原基线的缺陷观察，不应重写为当前修复结果。
