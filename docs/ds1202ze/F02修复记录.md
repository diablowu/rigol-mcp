# F02 DS1000Z-E 波形传输格式修复

分支：`codex/binary-waveform-transfer`，基于已完成 F01 的 `codex/model-aware-channels`。实施基线：`3f19030ee3ff3b6ecb62b7071ceb479f1ffa5b0d`。

DS1202Z-E 原先复用四通道 DS1000Z 的 ASCII 波形读取，要求响应带 `#N<长度>` 数据块头；专用编程手册仅明确规定 BYTE/WORD 使用该块头，对 ASCII 则描述为直接电压 CSV。目标固件的 ASCII 帧未经实机验证，因此本次选择手册明确定义的 **NORM/BYTE**，避免依赖这一未证实的协议假设。

依据：[RIGOL DS1000Z-E 英文编程手册](https://www.rigol.com/dam/global/downloads/brochures/en/program-guide/oscilloscopes/DS1000ZE_ProgrammingGuide_EN.pdf)，印刷页 2-176、2-178、2-179、2-182（本地 PDF 第 192、194、195、198 页）；中文专用手册 PDF 第 176、178、180-182 页。

## 实现

- 新增 `DS1000ZEDriver`，通过 IDN 型号字段匹配 DS1202Z-E/DS1102Z-E，在通用 DS1000Z 匹配之前选择。截图、测量、光标等命令仍复用原系列驱动。
- `get_waveform` 根据驱动选择格式和解码方式。Z-E 使用 `:WAV:MODE NORM`、`:WAV:FORM BYTE`，显式设置 STAR=1、STOP=1200，消除其他程序遗留读取窗口的影响。DS1054Z 等原 DS1000Z 和 DHO 保留原有 ASCII 电压解析。
- BYTE 数据块复用现有后端区分：@py 按长度读取；@ivi 使用原生消息读取。整个 Z-E 数据读取期间关闭终止符匹配，即使样本包含 0x0A，也不会作为文本换行截断。成功或异常时恢复读取终止符。
- 根据本次 preamble 换算，不将原始字节作为电压，也不重复乘以探头倍率。Python 整数运算避免无符号字节减法回绕。

```text
voltage[i] = (byte[i] - yorigin - yreference) * yincrement
time[i] = xorigin + (i - xreference) * xincrement
```

这里 STAR 固定为 1，`i` 从 0 开始。结果继续提供原有 `times_s`、`voltages_v`、点数、幅值统计和警告；MCP 工具调用参数及返回结构不变。

- 数据为空时保留原有有限时长轮询。发生轮询或初始时间间距为 0 时，在解码前刷新完整 preamble，保证电压标定也使用刷新后的参数。
- Z-E 解码校验 10 字段、BYTE/NORM、有限且有效的标定参数、1..1200 点范围及 preamble/载荷点数一致性。错误时不返回看似有效的统计。
- 给 bytecount 公共读取路径补充声明长度与实际读取长度的校验；一个带 LF 结尾的短包不能被当成完整 BYTE 记录。

## 验证与边界

`uv run --extra test pytest`：**183 passed**，包括原有 157 项与新增 26 项 F02 回归。F01 的波形 fake 已调整为目标型号现在实际使用的 BYTE 格式。

新增验证包括两个 Z-E 型号和两种后端、全部 0..255 字节（含 0x00/0x0A/0xFF）、非零 origin/reference、负电压与统计、终止符异常恢复、空数据及标定刷新、格式或点数不一致、无效标定和短包，以及旧 DS1000Z/DHO 的 ASCII 结果和 MCP 数组输出兼容。

这次修复仍读取屏幕 NORM 波形，没有实现 RAW 深存储。数据块头/尾部的全面容错和损坏会话恢复仍属于 F06；采集动作重试语义仍属于 F03。本次不推断目标机的真实 ASCII 帧形式，不把离线通过等同于实机验证。

实机验收应记录真实 IDN/固件和 VISA 后端，用已知低压信号验证不同偏置、探头倍率和档位下 BYTE 波形与屏幕/硬件测量的一致性，并确认完整窗口下 preamble 点数与载荷长度一致。
