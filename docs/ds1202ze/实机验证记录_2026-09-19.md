# DS1202Z-E MCP 实机验证记录（2026-09-19）

## 验证对象

- 设备：RIGOL DS1202Z-E（序列号不写入仓库）
- 固件：`00.06.04`
- 连接：以太网，目标位于本地私有网络
- 输入：CH1 接示波器内置校准信号，CH2 关闭
- 分支：`codex/binary-waveform-transfer`

## 结论

MCP stdio 端到端链路可用。真实 MCP 客户端完成了设备识别、状态读取、测量、
1200 点 BYTE 波形、游标、通道/时基/触发设置、STOP/RUN/SINGLE、自动量程、截图和
错误队列检查。测试结束前已恢复原有通道、时基、触发和游标状态，并恢复连续采集。

本次还复现并修复了 raw socket 二进制块尾部处理问题：DS1202Z-E 的 LAN 波形块可能在
头部声明的最后一个 payload 字节处结束，旧实现强制再读取一个 LF，因而超时并占住设备
的单客户端 SCPI 服务。新实现严格按块头长度读取 payload，再以短超时兼容性地消费可选
LF；同时增加 `RIGOL_LAN_PROTOCOL=vxi11`，可通过官方 VISA 地址
`TCPIP0::<ip>::INSTR` 使用 VXI-11。

## 缺陷复现与修复

旧的 `_read_block_via_bytecount` 读取 `data_length + 1` 字节，并硬性要求最后一字节是
换行符。真实设备在 raw LAN 的 BYTE 波形响应上没有提供该额外字节，导致三次读取重试
均等待超时；设备的 5555 服务随后保持等待旧连接，新的 `*IDN?` 也无法得到响应。

修复后的行为：

1. 读取 `#N<length>` 块头。
2. 精确读取 `<length>` 个 payload 字节。
3. 用 100 ms 超时探测并消费可选 LF；无 LF 时正常完成。
4. 保持 NI-VISA 原有基于消息边界的读取路径。
5. 提供 VXI-11 LAN 传输选项，便于诊断和恢复。
