# DS1202Z-E MCP 实机验证记录（2026-09-19）

## 设备与测试方式

- RIGOL DS1202Z-E，固件 `00.06.04`；序列号不提交到仓库。
- CH1 接示波器内置校准信号，CH2 关闭。
- 使用真实 MCP stdio 客户端，检查 `isError`、识别失败文本、返回数据和后续会话可用性。
- raw 模式使用 TCP 5555；最终版本对 DS1000Z-E 的错误队列读取使用 VXI-11，其他命令保持 raw 传输。

## 两个分支独立验证

| 分支及范围 | 离线结果 | 实机结果 |
|---|---|---|
| `codex/model-aware-channels`，`3f19030`，F01 | 157 passed | 两通道 schema、只返回 CH1/CH2 的状态、CH1 原值写回、CHAN3 拒绝及随后再次识别全部通过 |
| `codex/binary-waveform-transfer`，F02 及通信修复 | 189 passed | 两次 1200 点 BYTE 波形、PNG 截图、错误队列检查及各次检查后的再次识别全部通过 |

F01 测试在 F01 原分支运行，未混入 F02 的 BYTE 驱动。F02 分支基于 F01 开发，
增加了 BYTE 解码和通信兼容处理。CHAN3 调用的 `isError=true` 是预期的 schema 拒绝；
其他调用必须成功，脚本不会把进程退出码为零当作全部工具通过。

## 最终 F02 回归结果

- 1200 点屏幕波形，时间间隔 2 µs；幅度范围约 -0.16 V 至 3.12 V，峰峰值约 3.28 V。
- 两次波形读取约 0.57 秒、0.63 秒。
- PNG 截图约 0.81 秒；检查返回图像的 PNG 文件签名。
- 波形后的错误队列返回 `No error`，随后 `idn` 正常。
- 截图后的错误队列返回 `No error`，随后 `idn` 正常；约 2 秒截图恢复等待属于服务器已有逻辑。
- CHAN3 在 MCP schema 层被拒绝。

此前通过 VXI-11 完成了频率、周期、Vpp、Vrms、游标、通道/时基/边沿触发写入、
STOP/RUN/SINGLE 和自动量程测试。测试后恢复了原有通道、时基、触发和游标设置并保持 RUN。
测量读数约为 1 kHz、3.28 Vpp、2.10 Vrms；运行中的不同采集帧会有小幅波动。

## 已确认的问题与修复

1. DS1000Z-E 使用 NORM/BYTE 波形，按 preamble 将整数样本转换为时间和电压。
2. 按数据块头声明长度读取 payload，并兼容可选 LF；截断数据仍报错。
3. 多次观察到 raw 链路在 `:SYSTem:ERRor?` 超时，而 VXI-11 查询可成功。
   最终采用 VXI-11 错误队列查询作为兼容方案，因此 raw 模式也需要网络可访问 VXI-11 服务。
4. 已直接复现并修复资源生命周期错误：PyVISA 会复用同一 `@py` 资源管理器，关闭临时
   查询的管理器会同时关闭主 raw 会话。现在仅关闭临时 VXI-11 资源，保留共享管理器。
5. 移除没有实机证据支持的“错误队列响应缺少 LF”逐字节读逻辑，其他型号保留普通 query。

早期将超时直接归因于“波形缺少 LF”“客户端超时取消”或“固件死锁”的说法并未完成
独立根因验证，不能视为已证实结论。缺少 LF 的支持是防御性兼容；已验证的是上述复现
现象、资源管理器的关闭行为，以及最终实现的连续调用结果。
